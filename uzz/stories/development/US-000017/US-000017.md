## US-000017 — Dev Mode CLI Flag

### User Story

```
AS A User
I WANT the CLI to accept a `--gui` flag and expose the GUI setting to the application
SO THAT the application can launch the standalone GUI application with embedded dev tools when requested
```

#### Status
DONE

#### Dependencies
- US-000016

#### Technical Context & Constraints
* **Target System**: CLI entry point and command-line parsing layer
* **Toolchain / Rules**: Java, PicoCLI per `project/development-framework.md`; keep parsing logic isolated from UI construction per `project/coding-standard.md`
* **Flag contract**: The `--gui` flag must be optional, must not interfere with existing flags (`--show-log`, `--echo`, `--key`, `--endpoint`, `--model`, `--system-prompt`), and must be queryable from the parsed options object
* **Replacement**: The `--gui` flag replaces the removed `--dev` and `--fx-render` flags
* **Phase**: MVP

#### Notes
See `notes.md`

### Acceptance Criteria

```gherkin
Scenario: --gui flag is accepted without errors
  Given ViberCLI is started with existing valid options
  When the --gui flag is added to the command line
  Then the application starts successfully
  And no parsing error is raised for the unknown flag

Scenario: Application can read GUI mode from parsed options
  Given the CLI options are parsed
  When the --gui flag was provided
  Then the options object reports GUI mode as enabled
  And when the --gui flag was omitted
  Then the options object reports GUI mode as disabled

Scenario: --gui does not interfere with other flags
  Given ViberCLI is started with --show-log and --gui
  When the application initializes
  Then both log viewer and GUI mode are enabled
  And no flag is silently ignored
```
