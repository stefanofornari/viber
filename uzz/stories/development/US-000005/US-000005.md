## US-000005 — Embeddable JavaFX Component

### User Story

```
AS A Developer
I WANT to embed ViberFX as a reusable component in my host JavaFX application
SO THAT I can integrate conversation capabilities without rebuilding the UI from scratch
```

#### Status
DONE

#### Dependencies
- US-000014

#### Technical Context & Constraints
* **Target System**: Host JavaFX desktop application
* **Toolchain / Rules**: JavaFX, CommonsFX, AtlantaFX per `project/development-framework.md`; reusable embeddable UI parts per `project/coding-standard.md`; avoid hard-coding provider-specific behavior into the core component
* **Phase**: MVP

#### Notes
See `notes.md`

### Acceptance Criteria

```gherkin
Scenario: Embed the ViberFX component in a host application
  Given a host JavaFX application
  And a ViberFX embeddable component is available
  When I add the component to the host application's scene
  Then the component renders correctly within the host application

Scenario: Host application controls the Conversation displayed
  Given a ViberFX component embedded in a host application
  When the host application sets a Conversation on the component
  Then the component displays the provided Conversation

Scenario: Host application receives updates from the component
  Given a ViberFX component embedded in a host application
  When the user interacts with the component to modify the Conversation
  Then the host application is notified of the change

Scenario: Component does not hard-code provider-specific behavior
  Given the embeddable component is in use
  When I review the component implementation
  Then no LLM-provider-specific logic is embedded in the core component
```
