## US-000069 — Load and Save Story Files

### User Story

```
AS A Developer
I WANT to load a story from and save it to a markdown file or string through the control's API, with errors reported to the host
SO THAT I can integrate the editor with files and tools without losing or corrupting stories
```

#### Status
DONE

#### Dependencies
- US-000064
- US-000065

#### Technical Context & Constraints
* **Target System**: UserStoryEditor public API
* **Toolchain / Rules**: Java NIO, JavaFX, JUnit 5, TestFX headless, AssertJ BDD; `uzz/project/coding_standard.md`

#### Notes
1. API: `load(Path)`, `load(String)`, `save(Path)`, `toMarkdown()`.
2. Errors (I/O, parse) are reported through a host-observable error property/handler, not by a modal dialog.
3. A failed load leaves the current story untouched.
4. Loading or saving resets the dirty state (see US-000072).

### Acceptance Criteria

```gherkin
Scenario: Load from file
  Given a valid story markdown file
  When the Developer calls load(path)
  Then the editor shows the story

Scenario: Save to file and reload
  Given the editor shows an edited story
  When the Developer calls save(path) and then load(path) on a new editor
  Then the second editor shows an equal story

Scenario: Load from string
  Given a valid story markdown string
  When the Developer calls load(markdown)
  Then the editor shows the story

Scenario: Malformed file
  Given a file that is not a valid story
  When the Developer calls load(path)
  Then the host is notified of a parsing error
  And the previously shown story is unchanged

Scenario: Missing or unwritable file
  Given a path that does not exist or cannot be written
  When the Developer calls load(path) or save(path)
  Then the host is notified of an I/O error
```
