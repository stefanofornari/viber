## US-000076 — Constrain Dependencies to Existing User Stories

### User Story

```
AS A User
I WANT the dependencies field to accept only IDs of existing user stories
SO THAT I cannot reference stories that do not exist
```

#### Status

#### Dependencies

#### Technical Context & Constraints
* **Target System**: UserStoryEditor dependencies field
* **Toolchain / Rules**: JavaFX FXML, AtlantaFX, TestFX headless, AssertJ BDD

#### Notes
1. **Deferred**: to be implemented after the core editor stories.
2. The set of known story IDs is supplied by the host (e.g. from `uzz/stories`); the editor does not scan the file system itself.
3. Open design points: validate-on-edit vs. auto-complete/pick-list.

### Acceptance Criteria

```gherkin
Scenario: Known ID accepted
  Given the host provides the known story IDs "US-000001" and "US-000002"
  When the user enters "US-000001" as a dependency
  Then the model contains "US-000001"

Scenario: Unknown ID rejected
  Given the host provides the known story IDs "US-000001"
  When the user enters "US-000999" as a dependency
  Then the model does not contain "US-000999"
  And the field shows a validation error

Scenario: No known IDs provided
  Given the host provides no known story IDs
  When the user enters any ID
  Then the behavior is that of US-000066 (unconstrained)
```
