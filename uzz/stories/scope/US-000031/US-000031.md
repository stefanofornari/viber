## US-000031 — ScopeActor Implementation

### User Story

```
AS A Product Owner
I WANT the ScopeAgent to serve as a drop-in replacement for the Actor role during the scoping phase
SO THAT I can interact with a specialized agent focused on feature scoping within the standard Viber conversation pattern
```

### Acceptance Criteria

```gherkin
Scenario: ScopeActor serves as drop-in replacement for Actor role
  Given I have initiated a scoping phase session
  When the scoping phase begins
  Then ScopeAgent takes the Actor role in the Viber-Actor conversation pattern
  And I can interact with ScopeAgent using standard Viber messaging

Scenario: ScopeActor reads files to gather context for scoping
  Given I am in a scoping session
  And there are relevant files in the project directory
  When ScopeAgent needs context for questioning
  Then ScopeAgent reads the relevant files
  And uses the information to inform its questions

Scenario: ScopeActor writes files to document scope
  Given I have answered all clarifying questions in the scoping phase
  When the scoping phase completes
  Then ScopeAgent writes the scope document to the appropriate location
  And the file is accessible for review

Scenario: ScopeActor guides me through gap analysis with targeted questions
  Given I am in a scoping session
  When I say "I want to build a todo app"
  Then ScopeAgent asks "Who are the primary users of this todo app?"
  And follows up with questions about features, platforms, and data needs
  And each question is relevant to creating a complete scope

Scenario: ScopeActor produces a structured scope document
  Given I have answered all clarifying questions
  When the scoping phase completes
  Then I receive a structured scope.md document
  And the document covers all required sections
```
