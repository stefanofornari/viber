## US-000044 — StoryActor

### User Story

```
AS A Product Owner
I WANT the StoryActor to serve as a drop-in replacement for the Actor role during the story generation phase
SO THAT I can interact with a specialized agent focused on generating INVEST-compliant user stories from scope documents within the standard Viber conversation pattern
```

#### Technical Context & Constraints
* **Target System**: Java application using LangChain4j actors
* **Toolchain / Rules**: Java, LangChain4j 1.21.0+, Maven per `uzz/project/development-framework.md`; TDD workflow per `uzz/project/development-framework.md`
* **Dependency**: Requires uzzo-workflow dependency (UzzoStoryAgent)
* **Phase**: MVP

#### Notes
The StoryActor uses the UzzoStoryAgent from uzzo-workflow to generate user stories from scope documents. It follows the same pattern as ScopeActor but uses the stories() method instead of scope(). The agent loads its system prompt from the shared user-story skill resource (uzz/skills/story/SKILL.md). FileSystemTools are provided for reading scope documents and writing generated stories. The actor integrates with both CLI and GUI AskTools for iterative clarification during story generation.

### Acceptance Criteria

```gherkin
Scenario: StoryActor serves as drop-in replacement for Actor role
  Given I have initiated a story generation phase session
  When the story generation phase begins
  Then StoryActor takes the Actor role in the Viber-Actor conversation pattern
  And I can interact with StoryActor using standard Viber messaging

Scenario: StoryActor reads files to gather context for story generation
  Given I am in a story generation session
  And there are relevant scope files in the project directory
  When StoryActor needs context for generating stories
  Then StoryActor reads the relevant scope files using kb-man skill guidance
  And uses the information to inform story generation

Scenario: StoryActor writes files to document generated stories
  Given I have provided a scope document for story generation
  When StoryActor generates user stories
  Then StoryActor writes individual story files to uzz/stories/<domain>/US-XXXXXX/
  And the files are accessible for review

Scenario: StoryActor produces INVEST-compliant user stories
  Given I provide a scope document to StoryActor
  When StoryActor generates user stories
  Then the generated stories follow INVEST principles
  And each story has a unique identifier (US-XXXXXX format)
  And each story has Gherkin acceptance criteria

Scenario: StoryActor uses AskTools for iterative clarification
  Given I am in a story generation session
  When StoryActor needs clarification on scope details
  Then StoryActor invokes AskTools methods (AskQuestion, AskSingleChoice, AskMultipleChoice, AskConfirmation)
  And the appropriate CLI or GUI implementation handles the user interaction
  And the user responses are returned to StoryActor

Scenario: StoryActor is configured with FileSystemTools
  Given a StoryActor is created
  Then FileSystemTools are available to the agent
  And the agent can read and write files within the project basedir
```
