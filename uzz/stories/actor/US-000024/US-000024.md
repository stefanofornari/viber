## US-000024 — Interaction Mode and Tool Policy Enforcement

### User Story

```
AS A Developer
I WANT an `InteractionMode` enum and a generic `HumanInTheMiddleWrapper` that intercepts tool execution based on `@ToolPolicy`
SO THAT I can control whether tools run automatically, require confirmation, or are blocked entirely
```

### Acceptance Criteria

```gherkin
Scenario: InteractionMode enum exposes ASK, AGENT, and INTERACTIVE
  Given the InteractionMode enum is available
  When I reference ASK, AGENT, or INTERACTIVE
  Then each mode is a distinct enum constant

Scenario: HumanInTheMiddleWrapper creates a proxy that preserves tool annotations
  Given a tool object is wrapped with HumanInTheMiddleWrapper
  When I invoke a method annotated with @Tool
  Then LangChain4j still recognizes it as a tool
  And the wrapper intercepts execution based on policy and mode

Scenario: ASK mode blocks all tool execution
  Given InteractionMode is ASK
  When any @Tool method is invoked
  Then the tool is not executed
  And a message indicating tools are disabled is returned

Scenario: AGENT mode executes all tools directly
  Given InteractionMode is AGENT
  When any @Tool method is invoked
  Then the tool executes without confirmation regardless of @ToolPolicy

Scenario: INTERACTIVE mode executes READONLY and INTERACTIVE tools immediately
  Given InteractionMode is INTERACTIVE
  When a READONLY @Tool method is invoked
  Then the tool executes without confirmation
  And when an INTERACTIVE @Tool method is invoked
  Then the tool executes without confirmation

Scenario: INTERACTIVE mode requires confirmation for READWRITE and UNKNOWN tools
  Given InteractionMode is INTERACTIVE
  When a READWRITE or UNKNOWN @Tool method is invoked
  Then the configured HumanInTheMiddle function is consulted
  And the tool executes only if the function returns true
```
