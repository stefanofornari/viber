## US-000063 — Status Line with Project Name and Working Directory

### User Story

```
AS A User
I WANT a read-only status line at the bottom of the ViberFX main window showing the project name and working directory
SO THAT I always know which project and directory Viber and its actors are operating on
```

#### Status
WIP

#### Dependencies
- US-000018

#### Technical Context & Constraints
* **Target System**: Standalone ViberFX desktop application (`MainAppWindow`) only; not the embeddable JavaFX component, Dev Mode window, `ViberNB` or `ViberCLI`
* **Toolchain / Rules**: Java 21, JavaFX 23.0.2, CommonsFX, AtlantaFX, Maven, JUnit 5, TestFX, AssertJ; keep UI construction separate from business logic per `uzz/project/coding_standard.md` and `uzz/project/development_framework.md`

#### Notes
1. The status line is rendered below the conversation/input `SplitPane`, spanning the window width.
2. The working directory is the JVM current working directory (`user.dir`), the same directory the actors' file tools are rooted at. Do not change how actors resolve it and do not make it configurable.
3. The full absolute path is shown, truncated in the middle when it does not fit; the full path is in a tooltip.
4. The project name is the first non-blank level-1 heading (`# `) of `uzz/project/overview.md`, resolved against the working directory. When the file is missing, unreadable, or has no such heading, the name of the working directory's folder is shown instead.
5. A missing or unreadable `overview.md` is not an error: no dialog, no exception, and the main window still opens.
6. Both values are read once at startup; the status line never refreshes.
7. Other `overview.md` fields, front matter and non-`#` first lines are not read. The application never creates, seeds or edits `overview.md`.
8. The status line is not selectable, clickable or editable and shows no other information.
9. The layout of the `SplitPane`, prompt row, radial slot and `scopePhaseIndicator` must remain unchanged.

### Acceptance Criteria

```gherkin
Scenario: Status line shows project name and working directory
  Given the working directory is "/work/acme"
  And "uzz/project/overview.md" has the first level-1 heading "# Viber"
  When the ViberFX main window opens
  Then a read-only status line is displayed at the bottom of the window below the SplitPane
  And it spans the window width
  And it shows the project name "Viber" and the absolute path "/work/acme"

Scenario: First level-1 heading wins
  Given overview.md contains "## Intro" followed by "# Alpha" and later "# Beta"
  When the ViberFX main window opens
  Then the status line shows the project name "Alpha"

Scenario: Missing overview.md falls back to the folder name
  Given the working directory is "/work/acme" and "uzz/project/overview.md" does not exist
  When the ViberFX main window opens
  Then the status line shows the project name "acme"
  And no dialog is displayed
  And the main window opens normally

Scenario: Unreadable overview.md falls back to the folder name
  Given overview.md exists but cannot be read
  When the ViberFX main window opens
  Then the status line shows the working directory's folder name as project name
  And no exception is surfaced to the user

Scenario: overview.md without a non-blank level-1 heading
  Given overview.md contains only text and a blank "# " heading
  When the ViberFX main window opens
  Then the status line shows the working directory's folder name as project name

Scenario: Long path is truncated in the middle with a tooltip
  Given the working directory path is longer than the available status line width
  When the ViberFX main window is displayed
  Then the path is truncated in the middle, keeping its beginning and end visible
  And hovering over the path shows a tooltip with the full absolute path
```
