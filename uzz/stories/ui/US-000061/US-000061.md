## US-000061 — Close and Archive a Chat

### User Story

```
AS A User
I WANT to close and archive a chat
SO THAT I can keep the complete conversation for future resumption without leaving its tab open
```

#### Status
WIP

#### Dependencies
- US-000002
- US-000020

#### Technical Context & Constraints
* **Target System**: Standalone ViberFX desktop application
* **Toolchain / Rules**: Java 21, JavaFX 23.0.2, CommonsFX, AtlantaFX, and Maven; use FXML where practical and follow `uzz/project/coding_standard.md` and `uzz/project/development_framework.md`

#### Notes
1. Provide a small archive icon button in each chat tab title, using the existing AtlantaFX framework and icon set.
2. Activating the button closes that tab and retains the complete conversation in persistent storage, including its chats and messages, for future resumption.
3. Do not add an interface to discover or resume archived conversations in this story.

### Acceptance Criteria

```gherkin
Scenario: Archive action is available on each chat tab
  Given the ViberFX application has multiple open chat tabs
  When I inspect the tab titles
  Then each tab title has a separate icon button to close and archive that chat

Scenario: Close and archive retains the complete conversation
  Given a chat tab contains a conversation with chats and messages
  When I activate its archive button
  Then that tab closes
  And the complete conversation is retained in persistent storage
  And other open chat tabs remain open

Scenario: Archived conversation remains stored after application restart
  Given I have closed and archived a chat
  When the ViberFX application is restarted
  Then the complete archived conversation remains in persistent storage for future resumption

Scenario: Archive action writes chat messages to the debug log
  Given a chat contains one or more messages
  When I activate its archive button
  Then the debug log records each message type and title or name
  And the debug log records whether each corresponding message pane is collapsed or unfolded
  And the debug log records each message's complete content with its original newlines
```
