## US-000060 — Radial Workflow Mode Selector

### User Story

```
AS A user
I WANT to select Scope, Story, Code, or Explore from a radial control that shows the active mode and fits the prompt area
SO THAT I can switch and understand workflow modes without opening the Actor menu or losing prompt space
```

#### Status
DONE

#### Dependencies
- US-000019
- US-000021
- US-000033
- US-000035
- US-000048
- US-000054

#### Technical Context & Constraints
* **Target System**: Standalone ViberFX desktop application
* **Toolchain / Rules**: Java 21, JavaFX 23.0.2, CommonsFX, AtlantaFX, Maven per `uzz/project/development-framework.md`; FXML descriptors whenever possible; UI construction separate from business logic per `uzz/project/coding-standard.md`
* **Component**: `com.github.stefanofornari:fx-radial-menu:1.0-SNAPSHOT` per `uzz/library/fx-radial-menu.md`
* **Phase**: MVP

#### Notes
1. Place an always-visible `RadialMenu` immediately left of the prompt `TextArea` in the standalone main window, in the same horizontal row.
2. Expose four wedges: Scope, Story, Code, and Explore. Keep all wedges visible; there is no collapse/expand step.
3. Reuse the existing actor-switch behavior: Scope calls `switchToScopeActor()`, Story calls `switchToStoryActor()`, Code calls `switchToCodingActor()`, and Explore calls `switchToLangChain4jActor()`.
4. Explore is a label/alias for the existing LLM mode. Do not introduce a separate `ExploreActor` class, and do not show a Scope/Story/Code phase indicator while Explore is active.
5. Keep the existing Actor menu and all its entries unchanged.
6. Preserve existing API-key validation and failure messages for LLM, Explore, and Code selection.
7. Add the radial-menu dependency to `pom.xml`.
8. Show the active mode in the central hub: Scope, Story, Code, or Explore. Show a neutral indicator when the active actor is Manual or LLM selected from the Actor menu.
9. Highlight the active wedge when a mode is selected from the radial control; clear the radial highlight after a menu-driven actor switch, while the hub still reflects an active Scope, Story, or Code phase.
10. Explore and LLM share `LangChain4jActor`; track the radial selection separately so the hub can distinguish Explore from a menu-selected LLM.
11. Bind the radial diameter to the current input area height so the whole control matches that height, remains circular, and keeps a fixed footprint that does not change on hover or selection.
12. Leave all remaining horizontal space to the prompt `TextArea`; the radial must not widen the input area.
13. Track height changes when the prompt grows or shrinks, and when a `QuestionsPane` is inserted while the prompt is constrained to `ASK_TOOL_PROMPT_HEIGHT`, without creating a layout feedback loop.
14. Keep the radial clear of the `scopePhaseIndicator` label below the prompt and of the conversation area above it.

### Acceptance Criteria

```gherkin
Scenario: Radial control appears beside the prompt
  Given the standalone ViberFX application is running
  When I inspect the input area
  Then a radial control is visible immediately left of the prompt TextArea
  And it exposes Scope, Story, Code, and Explore wedges

Scenario: Selecting Scope activates the scoping mode
  Given the radial control is visible
  And a different mode is active
  When the user selects the Scope wedge
  Then ScopeActor becomes the active actor
  And subsequent prompts are handled by scoping behavior

Scenario: Selecting Story activates the story generation mode
  Given the radial control is visible
  And a different mode is active
  When the user selects the Story wedge
  Then StoryActor becomes the active actor
  And subsequent prompts are handled by story generation behavior

Scenario: Selecting Code activates the coding mode
  Given the radial control is visible
  And a different mode is active
  When the user selects the Code wedge
  Then CodingActor becomes the active actor
  And subsequent prompts are handled by coding behavior

Scenario: Selecting Explore activates the same mode as the LLM menu item
  Given the radial control is visible
  When the user selects the Explore wedge
  Then LangChain4jActor becomes the active actor
  And subsequent prompts are handled exactly as when LLM is selected from the Actor menu
  And no Scope, Story, or Code phase indicator is displayed

Scenario: Existing Actor menu remains available
  Given the radial control is visible
  When the user opens the Actor menu
  Then Manual, LLM, Scope, Story, and Coding items are present
  And each item keeps its existing behavior

Scenario: Selecting a mode without credentials preserves the previous actor
  Given no API key is configured
  And Manual is the active actor
  When the user selects the Explore or Code wedge
  Then the same validation and failure message is shown as for the corresponding Actor menu item
  And the previously active actor remains active

Scenario: Hub shows the mode selected from the radial
  Given the radial control is visible
  When the user selects the Scope, Story, Code, or Explore wedge
  Then the central hub displays the selected mode name
  And the selected wedge is highlighted

Scenario: Hub reflects a phase selected from the Actor menu
  Given the radial control is visible
  When the user selects Scope, Story, or Coding from the Actor menu
  Then the central hub displays the corresponding phase
  And the radial wedge highlight is cleared

Scenario: Hub shows a neutral indicator for menu-selected Manual or LLM
  Given the radial control is visible
  When the user selects Manual or LLM from the Actor menu
  Then the central hub shows the neutral indicator
  And the hub does not display Explore
  And no phase indicator is displayed

Scenario: Hub distinguishes Explore from menu-selected LLM
  Given the radial control is visible
  When the user selects Explore from the radial control
  Then the central hub displays Explore
  When the user then selects LLM from the Actor menu
  Then the central hub shows the neutral indicator

Scenario: Active mode updates without restart
  Given the application is running with any active mode
  When the user switches to another actor or radial mode
  Then the hub and wedge highlight update immediately
  And no application restart is required

Scenario: Radial diameter matches and tracks the input area height
  Given the standalone ViberFX application is running
  When I inspect the input area at startup and after resizing the window
  Then the radial control diameter equals the current input area height
  And the control remains circular

Scenario: Radial tracks input height changes caused by AskTools
  Given the radial control is visible
  And the prompt is displayed at its normal height
  When a QuestionsPane is inserted and the prompt is constrained to ASK_TOOL_PROMPT_HEIGHT
  Then the radial diameter tracks the new input area height
  And the control remains circular
  And the AskTools pane remains usable

Scenario: Radial does not reduce prompt width
  Given the radial control is visible
  When the user types a long prompt or the window is resized
  Then the radial keeps its fixed circular footprint
  And the prompt TextArea keeps all remaining horizontal space
  And the input area does not widen because of the radial control

Scenario: Radial does not overlap adjacent content
  Given the radial control is visible
  When the input area changes size
  Then the radial does not overlap the scope phase indicator
  And the radial does not overlap the conversation area
```
