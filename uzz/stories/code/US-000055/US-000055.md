## US-000055 — CLI Integration: CodingActor Selection

### User Story

```
AS A Developer
I WANT to select CodingActor in ViberCLI
SO THAT I can start coding work from the terminal
```

#### Technical Context & Constraints
* **Target System**: ViberCLI terminal application
* **Toolchain / Rules**: Java 21, Maven; follow `uzz/project/development-framework.md` and `uzz/project/coding-standard.md`

#### Notes
1. Provide a CLI selection mechanism consistent with the existing actor-selection conventions.

### Acceptance Criteria

```gherkin
Scenario: User selects CodingActor from the CLI
  Given ViberCLI is running
  When the user selects CodingActor using the CLI actor-selection mechanism
  Then subsequent prompts are handled by CodingActor

Scenario: CodingActor cannot be initialized
  Given ViberCLI is running with another actor active
  And CodingActor initialization fails
  When the user selects CodingActor
  Then the CLI reports the initialization failure
  And the previously active actor remains selected

Scenario: Normal CLI operation remains available
  Given the user has not selected CodingActor
  When the user sends a prompt to the active normal actor
  Then ViberCLI handles the prompt using that actor
```
