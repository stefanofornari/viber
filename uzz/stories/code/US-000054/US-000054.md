## US-000054 — GUI Integration: CodingActor Option

### User Story

```
AS A Developer
I WANT to select CodingActor in the GUI
SO THAT I can start coding work from ViberFX
```

#### Status
DONE

#### Dependencies
- US-000053
- US-000021

#### Technical Context & Constraints
* **Target System**: ViberFX standalone JavaFX application
* **Toolchain / Rules**: Java 21, JavaFX, Maven; use FXML where practical and follow `uzz/project/development-framework.md` and `uzz/project/coding-standard.md`

#### Notes
1. Follow the existing GUI actor-selection pattern.

### Acceptance Criteria

```gherkin
Scenario: User selects CodingActor from the GUI
  Given ViberFX is running with a chat open
  When the user selects CodingActor from the actor selector
  Then subsequent prompts are handled by CodingActor
  And the GUI indicates that the Coding Phase is active

Scenario: Coding Phase indication is distinct
  Given CodingActor is active in ViberFX
  When the user observes the active conversation
  Then a visible indicator identifies the Coding Phase
  And the indicator distinguishes it from normal, scoping, and story-generation modes

Scenario: CodingActor cannot be initialized
  Given ViberFX is running with another actor active
  And CodingActor initialization fails
  When the user selects CodingActor
  Then the GUI reports the initialization failure
  And the previously active actor remains selected
```
