## US-000053 — CodingActor

### User Story

```
AS A Developer
I WANT a CodingActor that handles my coding requests
SO THAT I can use the existing coding agent through Viber
```

#### Status
DONE

#### Dependencies
- US-000008
- US-000010

#### Technical Context & Constraints
* **Target System**: Java application using LangChain4j actors
* **Toolchain / Rules**: Java 21, LangChain4j, Maven; TDD workflow per `uzz/project/development-framework.md`

#### Notes
1. Delegate coding requests to the existing `UzzoCodeAgent` from `uzzo-workflow`; do not implement a new agent, model, prompt, or coding-tool set.
2. Follow the existing actor and streaming-response contracts.
3. Apply the existing `@ToolPolicy` classification to each coding tool method exposed to the agent according to its behavior. This story does not add runtime policy enforcement or approval flows.

### Acceptance Criteria

```gherkin
Scenario: CodingActor handles a coding request
  Given CodingActor is configured with UzzoCodeAgent
  When a user sends a coding request through Viber
  Then the request is delegated to UzzoCodeAgent
  And the agent response is returned through the standard Actor message contract

Scenario: CodingActor streams agent responses
  Given UzzoCodeAgent produces a response incrementally
  When CodingActor processes the response
  Then response messages are emitted incrementally through the streaming Actor contract

Scenario: Coding tools carry policy classifications
  Given coding tools are exposed to UzzoCodeAgent
  When CodingActor makes the tools available
  Then each exposed coding tool method has an existing `@ToolPolicy` classification appropriate to its behavior
  And no runtime policy enforcement is added by this story

Scenario: CodingActor reports agent failures
  Given UzzoCodeAgent fails while handling a coding request
  When CodingActor processes the failure
  Then Viber reports the failure using its Actor error behavior
  And the conversation remains usable for a subsequent message
```
