# User Stories for Domain: JavaFX UI

## [US-000018] ViberFX Standalone Application Entry Point
**As a** user,
**I want** to launch Viber as a standalone JavaFX desktop application,
**So that** I can view and interact with a conversation through a GUI without using the command line.

### Technical Context & Constraints
* **Target System**: Standalone JavaFX desktop application
* **Toolchain / Rules**: JavaFX, CommonsFX, AtlantaFX per `uzz/specs/development-framework.md`; FXML descriptors whenever possible; UI construction separate from business logic per `uzz/specs/coding-standard.md`
* **Prerequisite**: `US-000014` (JavaFX Conversation Output Rendering), `US-000015` (CLI-triggered JavaFX Rendering) are complete
* **Coexistence**: `ViberCLI` remains available; this US adds the standalone GUI as an alternative interface

### Acceptance Criteria
```gherkin
Scenario: Application launches as a standalone JavaFX window
  Given the ViberFX application is started without CLI flags
  When the application initializes
  Then a JavaFX window opens
  and the window is visible and resizable

Scenario: AtlantaFX styles are applied
  Given the ViberFX application is started
  When the JavaFX window is created
  Then Application.setUserAgentStylesheet is called with an AtlantaFX stylesheet
  and the stylesheet is set before any Scene is instantiated

Scenario: Conversation is displayed using the existing JavaFX renderer
  Given the ViberFX application is running
  and a Conversation containing Chats and Messages exists
  When the Conversation is set on the renderer
  Then the JavaFX renderer displays all Chats and Messages
  and Chats appear left to right and Messages appear top to bottom within each Chat

Scenario: Application serves as a standalone demo
  Given the ViberFX application is packaged and distributed
  When a user runs the application without any CLI flags
  Then the standalone GUI application starts
  and the user can view the conversation purely through the GUI
```
