# User Stories for Domain: UI

## [US-000012] Streaming CLI Rendering
**As a** Developer,
**I want** VibeChatCLI to render messages as they arrive,
**So that** I see partial output while the LLM is generating.

### Technical Context & Constraints
* **Target System**: Terminal application
* **Toolchain / Rules**: Java per `uzz/specs/development-framework.md`; TDD workflow per `uzz/specs/development-framework.md`

### Acceptance Criteria
```gherkin
Scenario: CLI renders streamed messages live
  Given VibeChatCLI is connected to a streaming Actor
  When the actor emits partial messages
  Then each message is rendered immediately
  and the conversation stays in a consistent state
```

### Implementation Notes
- `VibeChatCLI.start()` now passes `msg -> renderConversation()` as the second argument to `actor.chat(chat, onMessage)`.
- Each `ChatMessage` emitted by the actor triggers an immediate re-render, so the user sees incremental output.
- The conversation remains consistent because the actor appends messages to the `Chat` before invoking the callback, and the renderer only reads from the immutable `Conversation` view.

## Test Coverage
- `VibeChatCLITest`: 3 tests covering initial prompt, conversation continuation, and exit behavior.
- Live rendering is verified by capturing `System.out` with System Lambda and asserting the emitted `ReplyMessage` content appears.
