# User Stories for Domain: Core Model

## [US-000001] Core Conversational Data Model
**As a** Developer,
**I want** a Conversation / Chat / Message data model that represents the Viber-Actor conversation structure,
**So that** I can build conversational applications on top of a well-defined data structure.

### Technical Context & Constraints
* **Target System**: Java library
* **Toolchain / Rules**: Follow Java conventions from `uzz/specs/coding-standard.md`; immutable data where practical; explicit types for readability

### Acceptance Criteria
```gherkin
Scenario: Create a Conversation with one Chat containing one Message
  Given the Conversation, Chat, and Message model classes are available
  When I create a Conversation and add a Chat with a single Message
  Then the Conversation contains exactly one Chat
  And the Chat contains exactly one Message

Scenario: A Conversation supports multiple Chats in order
  Given an empty Conversation
  When I add two Chats to the Conversation
  Then the Conversation contains exactly two Chats
  and the Chats are ordered by insertion

Scenario: A Chat supports multiple Messages in order
  Given an empty Chat
  When I add two Messages to the Chat
  Then the Chat contains exactly two Messages
  and the Messages are ordered by insertion

Scenario: Messages have distinct types
  Given a Message class is available
  When I create Messages of type prompt, reply, thought, tool execution request, and tool execution response
  Then each Message retains its assigned type

Scenario: Viber and Actor roles are distinguishable
  Given a Message class is available
  When I create a Message from a Viber and a Message from an Actor
  Then each Message correctly records its sender role
```
