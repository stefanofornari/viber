# User Stories for Domain: Actor

## [US-000010] Streaming Actor Contract and LangChain4j Streaming
**As a** Developer,
**I want** `Actor.chat(Chat, Consumer<ChatMessage>)` to emit messages incrementally,
**So that** the conversation model receives granular messages as the LLM generates them.

### Technical Context & Constraints
* **Target System**: Java application
* **Toolchain / Rules**: Java per `uzz/specs/development-framework.md`; TDD workflow per `uzz/specs/development-framework.md`

### Acceptance Criteria
```gherkin
Scenario: Actor emits messages incrementally
  Given an Actor supporting streaming
  When I call chat with a callback
  Then multiple ChatMessage instances are emitted through the callback
  and the conversation is updated after each message

Scenario: LangChain4jActor streams partial chunks
  Given LangChain4jActor is configured with a StreamingChatModel
  When the model returns partial chunks
  Then each chunk is appended as a separate ReplyMessage
  and content type is text/plain

Scenario: Tool executions are still reported atomically
  Given a streamed response that triggers a tool execution
  When the tool is invoked
  Then the tool request/response messages are appended
  and streaming resumes afterward
```

### Implementation Notes
- Sync `Actor.chat(Chat)` was replaced with async `void chat(Chat chat, Consumer<ChatMessage> onMessage)`.
- `ChatMessage` gained a `default String contentType()` method returning `"text/plain"`.
- `LangChain4jActor` now builds an `AiServices` proxy backed by `StreamingChatModel` whose service method returns `TokenStream`.
- Partial text chunks are forwarded via `TokenStream.onPartialResponse` as individual `ReplyMessage` instances.
- Intermediate tool requests and tool execution results are forwarded via `onIntermediateResponse` and `onToolExecuted`.
- A `CountDownLatch` plus an `AtomicBoolean` guard ensures the final `ReplyMessage` is only appended once, avoiding duplicate completions when no partial chunks arrive.
- `StdInStdOutActor` was adapted to emit exactly one `ReplyMessage` through the callback.

## Test Coverage
- `LangChain4jActorTest`: 7 tests covering null guards, duplicate-chat prevention, prompt delivery, message appending, multi-chunk streaming, and tool callback emission.
