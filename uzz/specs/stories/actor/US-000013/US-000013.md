# User Stories for Domain: Actor

## [US-000013] Token Usage Capture
**As a** Developer,
**I want** LangChain4jActor to capture token usage from the LLM response and expose it through the conversation model,
**So that** I can track API costs and understand model consumption per exchange.

### Technical Context & Constraints
* **Target System**: Java application
* **Toolchain / Rules**: Java per `uzz/specs/development-framework.md`; TDD workflow per `uzz/specs/development-framework.md`

### Acceptance Criteria
```gherkin
Scenario: Token usage is captured from streaming response
  Given LangChain4jActor is configured with a StreamingChatModel
  When the model completes a response
  Then the token usage from ChatResponseMetadata is captured
  and the token usage is accessible from Chat.tokenUsage() after the exchange

Scenario: Token usage is captured from non-streaming response
  Given LangChain4jActor is configured with a non-streaming ChatModel
  When the model returns a response
  Then the token usage from ChatResponseMetadata is captured
  and the token usage is accessible from Chat.tokenUsage() after the exchange

Scenario: Missing token usage leaves Chat.tokenUsage() null
  Given a model response does not include token usage metadata
  When the chat exchange completes
  Then Chat.tokenUsage() returns null
```

### Implementation Notes
- `ChatResponseMetadata.tokenUsage()` provides `TokenUsage` with `inputTokenCount()`, `outputTokenCount()`, and `totalTokenCount()`.
- `Chat` was extended with a `tokenUsage()` getter/setter to store usage per exchange.
- `LangChain4jActor.chat()` captures token usage from `ChatResponse.metadata().tokenUsage()` in the streaming path and sets it on the `Chat`.
- Non-streaming `StdInStdOutActor` does not currently capture token usage because `STDIOActor` does not receive metadata from the counterpart; this is acceptable for now.
