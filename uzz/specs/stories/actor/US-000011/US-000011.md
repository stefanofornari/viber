# User Stories for Domain: Actor

## [US-000011] Reasoning Message Capture and Rendering
**As a** Developer,
**I want** LangChain4jActor to capture reasoning/thinking tokens from the LLM and emit them as `ThoughtMessage` instances in the conversation flow,
**So that** internal model reasoning is visible in the conversation alongside user prompts and replies.

### Technical Context & Constraints
* **Target System**: Java application
* **Toolchain / Rules**: Java per `uzz/specs/development-framework.md`; TDD workflow per `uzz/specs/development-framework.md`

### Acceptance Criteria
```gherkin
Scenario: Reasoning tokens are captured and emitted as ThoughtMessage
  Given LangChain4jActor is configured with a StreamingChatModel that produces reasoning tokens
  When the model emits reasoning content during streaming
  Then a ThoughtMessage is appended to the Chat for each reasoning segment
  and the onMessage callback receives the ThoughtMessage
  and the conversation is updated

Scenario: Reasoning messages are rendered alongside regular messages
  Given a conversation contains both ReplyMessage and ThoughtMessage instances
  When the conversation is rendered
  Then ThoughtMessage content is displayed with a distinct visual indicator
  and the conversation order is preserved

Scenario: Non-reasoning models continue to work without ThoughtMessage emission
  Given LangChain4jActor is configured with a model that does not produce reasoning tokens
  When a normal chat exchange occurs
  Then only ReplyMessage and tool messages are emitted
  and no ThoughtMessage instances are created
```

### Implementation Notes
- `ThoughtMessage` already exists in `ste.ai.viber.model` and is rendered by `StringRenderer`.
- `LangChain4jActor` must detect reasoning tokens from the streaming response and emit `ThoughtMessage` through the `onMessage` callback.
- Reasoning content may arrive through a dedicated callback on `TokenStream` or be identifiable within `PartialResponse`; exact mechanism depends on LangChain4j API availability.
