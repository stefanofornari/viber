# User Stories for Domain: Actor

## [US-000028] FileSystemTools Policy-Enforced Execution
**As a** LLM,
**I want** filesystem tool calls to respect interaction mode policies and require human confirmation for write operations,
**So that** I can safely interact with project files in INTERACTIVE and ASK modes.

### Technical Context & Constraints
* **Target System**: Java application using LangChain4j actors
* **Toolchain / Rules**: Java, Byte Buddy per `uzz/specs/development-framework.md`; TDD workflow per `uzz/specs/development-framework.md`
* **Dependency**: Builds on US-000024 (Interaction Mode and Tool Policy Enforcement), US-000025 (CLI Confirmation), and US-000026 (JavaFX Confirmation)

### Acceptance Criteria
```gherkin
Scenario: INTERACTIVE mode executes READONLY filesystem tools without confirmation
  Given InteractionMode is INTERACTIVE
  and the actor is configured with filesystem tools
  When the LLM invokes readFile, findFiles, searchInFile, or listFilesInDirectory
  Then the tool executes without confirmation

Scenario: INTERACTIVE mode requires confirmation for READWRITE filesystem tools
  Given InteractionMode is INTERACTIVE
  and the actor is configured with filesystem tools
  When the LLM invokes createFile, deleteFile, createDirectory, or deleteDirectory
  Then the user is prompted for confirmation via the appropriate UI (CLI or GUI)
  and the tool executes only if approved

Scenario: ASK mode blocks all filesystem tool execution
  Given InteractionMode is ASK
  and the actor is configured with filesystem tools
  When the LLM invokes any filesystem tool
  Then no tool is executed
  and a message indicating tools are disabled is returned

Scenario: Denied tool execution returns an error to the LLM
  Given InteractionMode is INTERACTIVE
  and the actor is configured with filesystem tools
  When the user denies a READWRITE tool execution
  Then the tool is not executed
  and an error message is returned to the LLM in the conversation
```

### Implementation Notes
- Filesystem tools are wrapped with `HumanInTheMiddleWrapper` when the actor is configured with an `InteractionMode` other than `AGENT`.
- The wrapper inspects `@ToolPolicy` on each tool method and applies the mode-specific policy:
  - `ASK`: block all execution
  - `AGENT`: execute all directly
  - `INTERACTIVE`: execute `READONLY`/`INTERACTIVE` immediately; require confirmation for `READWRITE`/`UNKNOWN`
- Confirmation is delegated to US-000025 (CLI) or US-000026 (JavaFX GUI) depending on the active UI.
- `AbstractTool.humanInTheMiddle()` is used to inject the mode-specific approval function.
- Filesystem tools' basedir confinement via `checkPath()` continues to operate unchanged.
- Tool request/response messages are appended to the conversation through the actor's streaming callback.
