# User Stories for Domain: Actor

## [US-000029] Standalone CLI FileSystemTools Integration
**As a** User,
**I want** the standalone CLI entry point to provide filesystem tools to the LLM,
**So that** I can use filesystem operations when running Viber from the terminal without the JavaFX GUI.

### Technical Context & Constraints
* **Target System**: Terminal/CLI user interface
* **Toolchain / Rules**: Java, Maven per `uzz/specs/development-framework.md`; TDD workflow per `uzz/specs/development-framework.md`
* **Dependency**: Builds on US-000027 (FileSystemTools Unrestricted Execution)

### Acceptance Criteria
```gherkin
Scenario: Standalone CLI provides FileSystemTools to the actor
  Given the application is started from the CLI without --gui
  and a valid API key is provided
  When the actor is created
  Then the actor is configured with FileSystemTools using the current working directory as basedir

Scenario: FileSystemTools are available in CLI mode alongside InputTool
  Given the application is running in CLI mode
  When the LLM invokes a filesystem tool
  Then the tool executes using the project's basedir
  and the result is returned to the LLM

Scenario: CLI FileSystemTools respect basedir confinement
  Given the CLI actor is configured with FileSystemTools
  When the LLM invokes a tool with a path outside the current working directory
  Then the tool rejects the path with an error
  and no filesystem operation is performed
```

### Implementation Notes
- `MainCommand.createActor()` is updated to include `FileSystemTools` alongside `InputTool`.
- The basedir defaults to `System.getProperty("user.dir")`, matching the current working directory from which the CLI was invoked.
- This story focuses only on the standalone CLI path; the JavaFX GUI path is covered by US-000027.
