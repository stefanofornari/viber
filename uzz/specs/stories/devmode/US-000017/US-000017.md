# User Stories for Domain: Dev Tooling

## [US-000017] Dev Mode CLI Flag
**As a** User,
**I want** the CLI to accept a `--dev` flag and expose the dev-mode setting to the application,
**So that** the application can launch additional test tooling windows when requested.

### Technical Context & Constraints
* **Target System**: CLI entry point and command-line parsing layer
* **Toolchain / Rules**: Java, PicoCLI per `uzz/specs/development-framework.md`; keep parsing logic isolated from UI construction per `uzz/specs/coding-standard.md`
* **Flag contract**: The new `--dev` flag must be optional, must not interfere with existing flags (`--fx-render`, `--show-log`, `--echo`, `--key`, `--endpoint`, `--model`, `--system-prompt`), and must be queryable from the parsed options object

### Acceptance Criteria
```gherkin
Scenario: --dev flag is accepted without errors
  Given ViberCLI is started with existing valid options
  When the --dev flag is added to the command line
  Then the application starts successfully
  and no parsing error is raised for the unknown flag

Scenario: Application can read dev mode from parsed options
  Given the CLI options are parsed
  When the --dev flag was provided
  Then the options object reports dev mode as enabled
  and when the --dev flag was omitted
  Then the options object reports dev mode as disabled

Scenario: --dev does not interfere with other flags
  Given ViberCLI is started with --fx-render and --dev
  When the application initializes
  Then both FX rendering and dev mode are enabled
  and no flag is silently ignored
```
